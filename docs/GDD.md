# GDD.md

## Project Summary

Inner Shadow is a **top-down dark fantasy action roguelite** built for a solo developer.

The game is no longer structured as a traditional small action RPG.  
It is now a **short run-based combat game** centered on Dark Essence, a risk/reward power system that replaces mana and drives the entire combat loop.

Project goals:
- fast to build
- easy to iterate
- strong combat feel
- high replayability through encounter variation
- finishable scope

Target run length:
- 10-20 minutes

Project target:
- a small polished vertical slice
- one complete run structure
- one boss
- strong replayable combat

This project should remain compact.  
Completeness matters more than content volume.

---

## High Concept

Valerius enters cursed combat grounds shaped by living darkness.  
To survive, he channels Dark Essence through aggressive abilities. The more Essence he generates, the stronger he becomes, but the closer he moves toward instability and frenzy.

Each run is a descent through a sequence of handcrafted arenas.  
The player survives encounters, takes simple upgrades, pushes Dark Essence to dangerous levels, and reaches a final boss that tests combat mastery and control.

---

## Core Gameplay Loop

1. Start run
2. Enter combat arena
3. Fight enemy wave or encounter
4. Use abilities to generate Dark Essence
5. Reach empowered, unstable, or frenzy states
6. Finish encounter
7. Choose 1 of 2-3 simple upgrades
8. Continue into the next arena
9. Reach boss arena
10. Win the run or die and restart

Loop priorities:
- combat should begin quickly
- downtime should stay minimal
- each arena should add pressure or variation
- upgrades should reshape the current run without adding complexity
- Dark Essence should remain the main source of tension throughout the run

## Combat Context

Combat is the core of the game.  
There is no exploration-heavy structure, large adventure map, or inventory-driven progression layer carrying the experience.

The player experience should focus on:
- responsive top-down action
- immediate combat readability
- quick decisions under pressure
- balancing power gain against loss of control

Combat pacing should be:
- fast to enter
- intense in short bursts
- easy to read
- built around escalating pressure

The feeling target is:
- aggressive
- dangerous
- readable
- rewarding when the player rides the edge of control

## Player

Name: Valerius

Valerius is the playable protagonist and the center of all combat tuning.

### Core ability set

- Basic Attack
- Shadow Strike
- Shadow Shield
- Shadow Bind

Design rules for abilities:
- always available
- never consume mana
- generate Dark Essence
- become more interesting when Dark Essence is high
- support aggressive play and combat flow

Abilities should be easy to tune and reuse.  
The initial set should stay small and purposeful.

## Dark Essence System

Dark Essence is the primary mechanic of Inner Shadow.

It is not a secondary resource and not a classic mana bar.  
It is the system that defines:
- player power
- combat tension
- upgrade synergy
- risk management
- run identity

If a design choice weakens Dark Essence, it is the wrong choice.

### Design Role

Dark Essence should:
- replace traditional mana usage
- reward aggressive ability use
- create rising tension during encounters
- push the player toward dangerous power spikes
- make every run feel volatile and unstable

The player should want more Essence because it increases power.  
The player should fear too much Essence because it threatens control.

That tension is the heart of the game.

### Essence Generation

Dark Essence is generated by:
- using abilities
- committing to combat actions
- offensive play patterns

Dark Essence should be easy to understand and easy to read during combat.

### Threshold Model

0-40 -> normal  
40-80 -> empowered  
80-100 -> unstable  
100 -> frenzy

### State Intent

#### Normal

- baseline control
- standard effectiveness
- low risk

#### Empowered

- clear increase in combat power
- encourages the player to stay aggressive
- should feel desirable, not incidental

#### Unstable

- high reward
- growing danger
- stronger pressure, penalties, or volatility
- player is close to losing control

#### Frenzy

- peak moment of the run
- explosive power spike
- dangerous and dramatic
- should feel like a climax, not only a punishment

Frenzy must be exciting.  
It can include drawbacks, but it should also create a memorable high-power window.

### Example Positive Effects

Higher Dark Essence may provide:
- increased damage
- increased attack speed
- lifesteal
- stronger ability effects
- shorter cooldowns
- on-hit or on-kill bonuses

### Example Risks

At high Dark Essence, the player may face:
- increased incoming damage
- reduced control precision
- self-harm or instability pulses
- temporary vulnerability after frenzy
- encounter pressure that becomes harder to manage

Risks should reinforce combat tension, not make the system frustrating to use.

### Upgrade Synergy

Run upgrades should often interact with Dark Essence.

Examples:
- gain lifesteal while above 60 Essence
- deal bonus damage while unstable
- frenzy lasts longer but drains health
- cooldowns shorten at high Essence
- gain more Essence but suffer stronger instability
- shield on entering frenzy

These upgrades should be simple modifiers, not new subsystems.

### Design Rules

- do not turn Dark Essence into mana
- do not block ability use because Essence is low
- do not hide the benefits of high Essence
- do not make frenzy only a failure state
- do make Dark Essence central to combat, upgrades, enemies, and boss design

## Progression

Progression is run-based and intentionally simple.

### In-Run Progression

After encounters, the player chooses 1 of 2-3 upgrades.

Upgrade types should stay simple:
- % damage increase
- attack speed
- lifesteal
- cooldown reduction
- ability-specific improvement
- Dark Essence generation change
- high-Essence bonus
- unstable-state modifier
- frenzy modifier

Good upgrade design:
- immediately understandable
- easy to implement
- easy to tune
- clearly impactful in combat

Avoid upgrades that require new UI-heavy or system-heavy support.

### Meta Progression

Meta progression should be minimal or absent.

If included at all, it should be very light:
- a small unlock
- a tiny starting modifier
- a simple persistent option

Do not build:
- talent trees
- long-term stat grind
- large unlock tracks
- economy layers
- progression currencies that require separate balancing

The run itself should be the main progression experience.

### Removed or Minimized Systems

The game should not depend on:
- complex inventory
- crafting
- loot rarity layers
- equipment management
- expansive item pools

If a progression idea increases implementation time and does not strengthen the run loop, remove it.

## Enemies

Enemy design should stay compact and reusable.

Use a small set of archetypes:
- melee
- ranged
- tank
- caster

Each archetype should have a clear role in encounters.

### Archetype Intent

#### Melee

- direct pressure
- forces movement
- fills space quickly

#### Ranged

- punishes passivity
- creates crossfire
- increases positional pressure

#### Tank

- absorbs damage
- slows arena flow
- protects other enemies

#### Caster

- creates disruption
- controls space
- adds timed threats or support pressure

Reuse these archetypes aggressively with:
- different group compositions
- pacing changes
- arena layout interactions
- encounter modifiers

Do not expand into a large enemy catalog unless absolutely necessary.

---

## Boss

Each run ends with one boss fight.

The boss exists to test everything the run has taught:
- positioning
- timing
- arena awareness
- damage windows
- Dark Essence control

Boss design should interact with the core system when possible.

Examples:
- punishes reckless frenzy timing
- creates moments where pushing Essence is powerful but dangerous
- forces the player to choose between control and burst

Boss scope rules:
- one boss is enough
- reuse existing combat systems where possible
- avoid custom one-off mechanics unless they add major value
- keep the fight readable in top-down view

The boss should feel like the climax of a run, not a separate game mode.

## Levels

The game does not use large traditional levels.  
It uses **modular handcrafted arenas / rooms** arranged into short runs.

### Arena Philosophy

The arena system exists to:
- reduce development cost
- improve encounter iteration
- support replayability without procedural generation
- keep content focused on combat

### Arena Rules

- target 5-8 arena types maximum
- arenas should be reusable
- arenas should be handcrafted, not procedurally generated
- each arena should support multiple enemy compositions
- each arena should support pacing variation
- each arena should stay small and readable

### Variation Sources

Reuse arenas with variation through:
- enemy combinations
- elite presence
- wave timing
- encounter intensity
- simple arena modifiers
- player upgrade combinations

### Arena Types (examples)

- open pressure arena
- choke-point arena
- split-lane arena
- pillar or cover arena
- circular survival arena
- boss staging arena

These are templates, not promises of final content count.

### Things To Avoid

- open world structure
- large maps
- exploration-heavy gameplay
- long traversal segments
- huge empty spaces
- content that exists only for scale

The environment should support combat first.

## Run Structure

A complete run should be short, punchy, and repeatable.

Example run structure:

1. entry arena
2. pressure arena
3. escalation arena
4. upgrade choice
5. mixed-threat arena
6. upgrade choice
7. pre-boss arena
8. boss arena

This structure can be tuned, but the key principles are:
- short total runtime
- fast restarts
- escalating pressure
- clear encounter rhythm
- strong finale

## Scope Rules

This is a solo-dev roguelite.  
Scope discipline is mandatory.

### Always prioritize

- reuse over expansion
- simple implementation over ambitious systems
- handcrafted modular content over large content sets
- combat feel over feature count
- a working vertical slice over future-proof design

### Do not add unless explicitly needed

- procedural generation systems
- complex meta progression
- crafting
- large inventory systems
- loot ecosystems
- multiple campaigns
- open world content
- narrative-heavy quest content
- large biome counts
- many bosses

### Development filter

Every feature should answer yes to these:
- does it strengthen the run loop?
- does it support Dark Essence?
- is it fast to build?
- is it easy to test?
- does it improve the chance of finishing the game?

If not, cut it.
